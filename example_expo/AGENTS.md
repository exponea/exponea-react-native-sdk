# Expo example app

Apply the root guide as well. Commands run from the repository root; paths are relative to the repository root. Keep `example_expo/README.md` and `documentation/expo.md` aligned with changes to this app or to the SDK's config plugin.

- `example_expo` is an Expo development-build version of [the example app](../example/AGENTS.md). It consumes the local SDK with `workspace:*` and its packaged config plugin (`app.plugin.js`). Expo Go is not supported.
- The Expo SDK and the React Native version it requires are pinned in `example_expo/package.json` and can differ from `example/`. `scripts/verify-expo-package.js` asserts the Expo major version and the SDK's `expo` peer range.
- Expo support is experimental. Do not describe it as stable in docs or release notes.

## Mirrored and generated files

- `example_expo/{src,__tests__,__mocks__,types}` are copies of the same folders in `example/`. Never edit them here: change `example/`, then run `yarn sync:expo-example`.
  - Declare intentional differences in `scripts/sync-expo-example.js`: `SUBSTITUTIONS` for text replaced while copying (only the iOS app group in `src/App.tsx` today), `EXPO_OWNED_FILES` for whole files the sync never touches.
  - The sync refuses to overwrite or delete a file it didn't write that Git can't restore; `--force` discards such files. It records what it wrote in the Git-ignored `example_expo/.sync-manifest.json`.
  - `yarn verify:expo` fails if the copies drift.
- Everything else in `example_expo/` belongs to the Expo app and is never synced: `app.config.js`, `plugins/`, `ExpoWatermark.tsx`, `index.js`, configs and assets.
- `example_expo/android/` and `example_expo/ios/` are generated by `yarn example_expo prebuild` (`expo prebuild --clean`). They are Git-ignored, must never be committed (`scripts/verify-expo-package.js` checks this) and are overwritten on every prebuild. Make native changes in `app.config.js`, the SDK plugin (`app.plugin.js`, `plugin/`) or `plugins/withExampleNativeHelpers.js`, then prebuild again.
- `plugins/native/` holds the app's own native helpers (`CustomerTokenStorage`, `TokenTracker`, `ExampleAuthProvider`), adapted by hand from `example/android` and `example/ios`. The sync and the drift check don't cover them: port helper changes from `example/` by hand. `plugins/withExampleNativeHelpers.js` copies them into the generated projects on every prebuild and reads the native Android SDK pin from the SDK's `android/build.gradle`.

## Configuration

- `app.config.js` owns the app identity (bundle identifier and Android package), the iOS app group, URL schemes, the SDK plugin options and the helper plugin. Its app group must equal the `to` value of the `src/App.tsx` substitution in `scripts/sync-expo-example.js`.
- `ExpoWatermark.tsx` wraps the shared app in a pointer-transparent overlay that is hidden from accessibility, so UI automation sees the same tree as in `example/`. Keep both properties.
- Push credentials (`google-services.json`, `GoogleService-Info.plist`, provisioning profiles, `.p8` keys) are Git-ignored local files registered for the Expo app's own identifiers. Never commit them or reuse the bare example's files.
- Check Expo dependency alignment with `npx expo install --check` from `example_expo/` (needs network).

## Commands

```bash
yarn example_expo typecheck
yarn example_expo test
yarn test:expo-plugin                      # config plugin unit tests, also part of root `yarn test`
yarn verify:expo                           # the three above + package contents and mirror drift
yarn sync:expo-example                     # after changing example/{src,__tests__,__mocks__,types}
yarn example_expo prebuild --no-install    # regenerate android/ and ios/; without --no-install it also runs pod install
yarn verify:expo-prebuild                  # assertions on the last prebuild output
yarn example_expo android                  # or ios; `yarn example_expo start` for later launches
```

- `example_expo/jest.config.js` uses the `react-native` preset, the root `jest.setup.js` and the mirrored `__mocks__/react-native-exponea-sdk.js`.
- `yarn example_expo typecheck` uses this app's `tsconfig.json`. Root `yarn typecheck` reports the same known errors in `example_expo/` as in `example/`.
- `verify:expo-prebuild` reads the last prebuild output, so run prebuild first. It hardcodes the expected native dependency coordinates; update it when native SDK pins change.

| Change touches                                   | Run                                                                                                                                      |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `example/{src,__tests__,__mocks__,types}`        | `yarn sync:expo-example`, `yarn verify:expo`                                                                                             |
| `app.plugin.js` or `plugin/`                     | `yarn test:expo-plugin`, prebuild, `yarn verify:expo-prebuild`, an Expo Android and iOS build; plugin options in `documentation/expo.md` |
| `app.config.js` or `plugins/`                    | Prebuild, `yarn verify:expo-prebuild`, an Expo native build                                                                              |
| Wrapper push entry points used by generated code | Prebuild, `yarn verify:expo-prebuild`, an Expo Android build (see [the Android guide](../android/AGENTS.md))                             |

## Manual checks

- Test push, rich push, links and lifecycle in a development build on a device or simulator, as in [the example guide](../example/AGENTS.md#credentials-and-manual-checks); report untested scenarios.
- Rich push on iOS needs the notification extensions, the app group and signing for the extension targets; see `documentation/expo.md`.
